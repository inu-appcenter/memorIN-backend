## 3. 캘린더 뷰 — BE에 날짜 조회 경로가 없다

스프린트 문서에는 완료로 체크돼 있으나, 게시물 조회 API에 **날짜로 범위를 좁히는 파라미터가 없다.**

```java
// PostController#getPostList — 받는 파라미터 전부
@RequestParam(required = false) UUID userId
@RequestParam(required = false) String cursor
@RequestParam(required = false) Integer size
```

`PostRepository.findUserFeed`는 `recorded_date DESC, id DESC` 정렬과 키셋 페이징만 하고, 특정 날짜/월로 거르지 않는다.

전체 피드를 받아 클라이언트에서 거르는 방식이라면 **커서 페이지네이션과 충돌**한다 — 탭한 날짜의 게시물이 뒤쪽 페이지에 있으면 화면에 나타나지 않는다.

→ FE 구현 방식 확인 후, 필요하면 `date` 또는 `from`/`to` 파라미터를 추가한다.
   `idx_posts_user_id (user_id, recorded_date DESC, id DESC)`가 이미 있어 인덱스 추가 비용은 없다.

## 4. 이번 정리에서 처리한 것 — main → develop 역머지

`develop`에 추천 피드 수정이 빠져 있었다.

#118(추천 피드 전면 500) 수정 PR #129가 `develop`이 아니라 **`main`에 직접 머지**되면서 두 브랜치가 갈라졌다.

| 브랜치 | `PostRepository.findRecommendationCandidates` |
| --- | --- |
| `main` | `AND p.created_at <= :asOf` — 정상 |
| `develop` (역머지 전) | `AND p.created_at <= : asOf` — 콜론 뒤 공백, `PSQLException` |

유일한 회귀 테스트 `RecommendedFeedQueryTest`도 `main`에만 있어 **`develop` CI가 이 결함을 잡을 수 없는 상태**였다. 머지 방향이 `develop → main` 한쪽뿐이라 시간이 지나도 자동으로 해소되지 않는다.

**이 PR에서 `main`을 `develop`으로 역머지해 해소한다.** (fast-forward, 충돌 없음)

> **교훈**: 핫픽스를 `main`에 직접 머지하면 `develop`은 영원히 고쳐지지 않는다.
> 긴급 수정이 `main`으로 갔다면 같은 날 역머지한다.
